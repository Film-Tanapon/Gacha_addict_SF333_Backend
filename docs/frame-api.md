# การเลือกกรอบผ่าน API

`PUT /api/profile` และ `PUT /api/users/:id` (แก้ไขได้เฉพาะบัญชีตัวเอง) รับ `frameUrl` ได้ โดยส่ง Bearer token ของเจ้าของบัญชี และใช้ค่า URL ตรงกับ `imageUrl` ที่ได้จาก `GET /api/frames`

```json
{
  "frameUrl": "/api/uploads/00000000-0000-4000-8000-000000000001.webp"
}
```

- กรอบฟรี (`price: 0`) ใช้ได้ทันที กรอบเสียเงินต้องมีรายการซื้อใน `UserFrame` ของบัญชีที่เรียก API มิฉะนั้นตอบ `403` โดยไม่แก้ไขข้อมูลหรือหักเหรียญ
- เซิร์ฟเวอร์ค้นกรอบจาก URL แล้วบันทึก `frameId`, `frameColor` และ `frameUrl` จากข้อมูลสินค้าให้ครบ ไม่ใช้ค่า URL หรือสีที่ปลอมแปลงมาคู่กับ ID
- หากส่ง `frameId` คู่กับ `frameUrl` ทั้งสองค่าต้องตรงกับสินค้ากรอบเดียวกัน มิฉะนั้นตอบ `400`
- URL หรือ ID ที่ไม่มีในร้านค้าตอบ `404` ไม่รับ URL รูปทั่วไปเป็นกรอบ
- ถ้ามีหลายสินค้าใช้ URL เดียวกัน ต้องส่ง `frameId` ระบุสินค้าด้วย มิฉะนั้นตอบ `400`
- ใช้ `PUT /api/frames/:id/select` เลือกด้วย ID ได้ตามเดิม และตรวจสิทธิ์ด้วยกฎเดียวกัน
- ส่ง `{"frameUrl": null, "frameColor": "#8b5cf6"}` เพื่อเอารูปกรอบออกและใช้สีกรอบแทน (เซิร์ฟเวอร์ล้าง `frameId` ด้วย) การส่งเพียง `frameColor` เปลี่ยนเฉพาะสีและไม่ล้างกรอบรูปเดิม

`POST /api/auth/register` รับ `frameUrl` ด้วยกฎเดียวกัน แต่เลือกได้เฉพาะกรอบฟรี เพราะบัญชีใหม่ยังไม่มีรายการซื้อ การสมัครด้วยสีกรอบพื้นฐานยังส่งเพียง `frameColor` ได้ตามเดิม

URL ต้องตรงกับค่าที่เก็บในสินค้า รวมทั้งรูปแบบ relative/absolute ไม่เปรียบเทียบเฉพาะชื่อไฟล์หรือ path เพื่อป้องกันการใช้ URL จาก host อื่นแทนรูปสินค้า
